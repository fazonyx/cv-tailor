# Project memory

Why this repository is shaped the way it is. Read before undoing something:
most of the odd-looking decisions below were made after watching the thing fail
on real content.

## Origin

cv-tailor is the generic, anonymised half of a private CV generator: one
Python/ReportLab script per job application, plus a set of rules the author
kept re-reading to avoid embellishing under deadline. The scripts were not
worth publishing - the rules and the verification loop were. Everything here
was rewritten from scratch around that idea; nothing of the private repository
was copied over.

## Decisions

**Facts and framing live in different files.** `profile.yaml` holds what is
true; an overlay per application holds how it is framed. This is what makes the
honesty rules enforceable rather than aspirational: an overlay can reorder,
drop and reword, and the loader refuses the fields that must stay factual
(`employer`, `employer_role`, `period`, `client`, `city`, anything on an
education entry). A CV line exists only as `- from: <fact-id>`.

**A mission `role` is reframable, a contract title is not.** The band above a
client mission carries the real employer and the real contract title; the line
below describes the mission and is framed for the offer. That distinction is
the whole reason the employer band exists.

**`gaps:` has two strengths.** The default entry may appear when marked
("ramp-up", "transferable", "basics"); `forbidden: true` may not appear at all.
The second one exists for the skill someone has genuinely never practised and
that offers keep demanding, and for wording that would simply be untrue ("AWS
Certified" while the exam is not passed). Marking is not enough there, because
the temptation is to mark it and move on.

**A cover letter may name a gap in order to deny it.** "I have not run
Kubernetes in production" is the honest sentence and must pass; "I run
Kubernetes in production" must not. Hence `allow_negation` on the letter scan
and not on the CV, where there is no room for a denial anyway. Without this the
letter check produced a false positive on the very first honest letter, and a
check that fires on correct content gets turned off.

**The margin rule is a band, not a floor.** Under ~15 mm the page reads as
cramped; over ~45 mm in the right column it reads as an unfinished draft. Both
are reported. The left column is exempt: white space in a sidebar is fine.

**Line heights derive from `leading`, not from constants.** They used to be
frozen millimetre values, so shrinking `size_body` freed almost no vertical
space - the theme offered a knob that did nothing. Found by running a dense
real profile through it, which overflowed by 17 mm with no working remedy.

**Translations fall back, loudly.** `tr()` prints another language rather than
crashing, which is right for a PDF and wrong for a silence, so a field
translated into some languages but not the rendered one fails the build. Only
what the application prints is checked; `fr: ""` is the way to leave a field
out of a page on purpose.

**PDFs are byte-reproducible** (`invariant=1`). ReportLab otherwise stamps a
date and a random id into every file, so a rebuild dirtied the tree and the
committed examples could not be reviewed.

**Console output never crashes on content.** An emoji in a tag used to take
down the build *while reporting that same emoji*, on any cp1252 console. The
one moment the tool has to speak is when the content is wrong.

**The README images are generated by `tools/preview.py`.** They came from a
throwaway script at first, which meant nobody could regenerate them after a
layout change and they would have drifted away from the real output.

## Found by running the loop end to end

The four commands were written before anyone had used them. Playing them once
from a clean clone, on an invented profile drafted from messy invented sources,
changed four things:

- **A `role:` override was silently dropped for salaried people.** The renderer
  preferred the contract title and stopped there, so everyone who is not a
  consultant got no framing at all - the feature the README leads with. Both
  now show: contract title first, because it is the fact, framing after it.
- **Short gap terms could not be written.** The advice was to prefer "Golang"
  over "Go" to avoid matching every "go" in a sentence, which meant the check
  missed the word people actually put on a CV. `case_sensitive: true` fixes the
  real case instead of working around it.
- **Unverified fields shipped silently.** Drafting a profile from old documents
  leaves guesses; a `# ?` comment marking one was read by nobody. The build now
  reports them until they are settled - the first draft of the dry run invented
  a notice period that nothing in the sources supported, and it went straight
  into a PDF.
- **Nothing listed the fact ids.** Writing `- from: vx-runtime` means knowing
  it exists, and the only way was scrolling the profile. `build.py --facts`
  prints them.

The other lesson has no code behind it: a first pass on a five-year profile
comes out half empty, and the honest answer is to put back a section rather
than to pad. That is now written in CLAUDE.md, because the instinct is to
invent something to fill the space.

**`applications/` is default deny.** It used to be a normal tracked folder,
with only a `applications/_*/` convention for local work - which protected
nobody, because the natural thing to name a folder is `acme`, not `_acme`.
Anyone using the template for real then had their offer, their reframed bullets
and a PDF carrying their name sitting as untracked files, one `git add -A` away
from a public fork. Now only the two example folders are tracked, and the
pre-commit hook blocks the rest even when forced.

## Deliberately not done

- **CI does not verify that the committed PDFs match a fresh build.** Tempting
  now that output is deterministic, but a different ReportLab version would
  turn `main` red for a reason a contributor cannot fix.
- **No Unicode fonts.** Base-14 PDF fonts mean no font files, no licensing
  question, no download - at the cost of Latin-1 only. The `charset` check
  turns that limit into a clear message instead of a square box. Anything
  beyond Latin script needs an embedded font, which is a different project.
- **No CLI, no plugins, no second layout, no JSON Resume import.** Scope is the
  feature.
- **The `figures` check only looks at reworded bullets.** Numbers invented
  directly in a skills row or a headline are not caught. Worth doing, not done.
- **The bilingual example sits at ~15.7 mm of bottom margin**, a few words away
  from failing CI. Left as is: it shows the rule biting on the page where it
  actually bites, since French runs longer than English.

## Conventions

- Everything public is in English: code, comments, docs, commit messages.
- Conventional commits, atomic, in the imperative.
- Commit identity: the `fazonyx` GitHub noreply address, never a real one.
